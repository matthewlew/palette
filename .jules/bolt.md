## 2024-05-24 - Memoizing Tile components with inline API objects
**Learning:** `React.memo` with shallow comparison fails on components that receive dynamically created objects as props (like the `likes` object in `Gallery.tsx` which exposes methods created inline). This leads to O(N) re-renders for every interaction. Furthermore, a custom `areEqual` function must dynamically iterate over all primitive props and fallback to specific checks only for the complex object, rather than hardcoding a whitelist. Hardcoding a whitelist omits important event handler props and introduces stale closure bugs, effectively breaking component functionality (like drag-and-drop).
**Action:** When memoizing list items that receive inline API objects, use a custom `areEqual` comparator that dynamically iterates through `prev` and `next` props using `for...in` to catch stable primitive changes, then add specific evaluation checks for the complex object's dynamic methods. Also verify that parent event handlers are properly stabilized with `useCallback` and accurate dependency arrays.

## 2024-06-25 - Strict list memoization for drag-and-drop performance
**Learning:** Hoisting a high-frequency interaction state (like `dragOverId` during drag-and-drop) to a top-level container component (`Gallery`) triggers 60fps full re-renders of that component. If derived list states (e.g. mapping, filtering, or Set creation for the gallery grid) are not wrapped in `useMemo`, they are synchronously re-computed on every frame, causing severe frame drops.
**Action:** When working in components that hoist interaction state like drag-and-drop, strictly wrap all O(N) array transformations and object instantiations in `useMemo` to safeguard the 60fps budget.
