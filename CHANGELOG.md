# Changelog

All notable changes to this project during our sessions will be documented in this file.

## [Unreleased] - 2026-07-29

### Added
- **A Colors list in the edit sheet — every stop, with its hex code visible.** Each row has a real swatch, an editable hex field, copy, lock and remove. It replaces a hidden 1×1 `<input type="color">` that was `.click()`ed when you tapped a stop: browsers anchor the OS picker to the input's box, so on desktop the picker opened in the corner of the sheet, nowhere near the color you tapped. Rows own real inputs, so the picker opens on the swatch you pressed. The hex codes are permanently visible because this is a tool for choosing colors and you cannot choose a better one than `#C2410C` without being told that's what you have. Tapping a stop on the canvas or the flow editor now selects it and scrolls to its row rather than firing a picker.
- **Copyable CSS.** A read-only box under the list holds the gradient as a ready-to-paste `background-image:` declaration, with a Copy button. Turrell is the one shape CSS cannot express as a single value — it is a stack of blurred elements — so that case is labelled as the approximation it is (`lib/cssSnippet.ts`) rather than handing over a snippet that doesn't match what's on screen.
- **Lock a color and generate around it.** The lock on a row pins that color; every palette the rolodex generates afterwards keeps it at that index and builds the rest around it. Locked colors take part in candidate *scoring*, not pasted on afterwards, so a candidate only wins if it harmonises with what's pinned — and the hex is written back verbatim rather than round-tripped through Oklch, which is lossy by a digit. Editing a pinned stop moves the pin with it; removing a stop shifts the pins above it down. A chip at the feed's top-left shows the pinned swatches and clears them in one tap, so a generator that has been told to hold one color never looks like a generator that has quietly broken.
- **Saving now visibly goes somewhere.** A copy of the gradient pops out of the Save pill, arcs across the screen and shrinks into the Gallery tab's thumbnail stack, which catches it with a bump. The old feedback was the button relabelling itself to "✓ Saved" — an acknowledgement of your tap, with nothing connecting it to where the palette landed. If the tab bar happens to be hidden (mobile edit sheet, idle fade) it is forced back for the flight: landing a thumbnail somewhere invisible communicates nothing. `prefers-reduced-motion` gets the bump without the travel.

### Added
- **Full-screen search on mobile.** Below 768px a live query takes over the gallery: the field and a Cancel stay, everything else goes. Measured before, 104px of chrome sat above the results and most of it did nothing for searching. Done by hiding rows in place rather than rendering an overlay, so the input keeps its DOM node and focus, the keyboard and the caret survive the transition. Desktop is unchanged — it has room for search and the gallery at once.
- **Shapes are searchable.** Search matched display names only, so the one attribute every palette definitely has — its geometry — could not be searched: typing "radial" looked for the *word* radial in generated names and missed every actual radial gradient. A shared vocabulary in `lib/shapeSearch.ts` maps what people type to a shape ("lines"/"stripes" → linear, "circular"/"round" → radial, "turrell"/"blocks" → square, "conic"/"pinwheel" → angular, "reflect" → mirror, "rays"/"cone" → fan). Shape words filter by geometry, remaining words still match the name, so "warm mirror" narrows to mirrored palettes named warm. Several shapes are OR'd, since a palette has exactly one. Both the local and the community pass parse through the same function.
- **Search results are grouped Yours, then Community.** Search only ever queried the Supabase `palettes` table, so it returned other people's palettes and never your own — and the Yours/Community toggle stayed visible and interactive while the results ignored it entirely. Your saved palettes are now matched locally by name and shown first, on the **first keystroke**, while the community query is still in flight behind its 400ms debounce. Your matches also survive a failed network call.
- **Back button on the full-screen create feed.** Top-left, same anchor and chevron as the editor's, so "leave this surface" is one gesture everywhere. It only renders where a caller passes `onBack`, so other `GradientPage` surfaces keep their own close chrome.

### Fixed
- **Tapping Search no longer zooms the page on iOS.** Safari zooms the viewport when a focused field's computed font-size is under 16px, and does not zoom back out — one tap left the whole app magnified and horizontally scrollable. The search box (13px), the shape filter `<select>` (13px) and the title rename field (15px) were all under it. A new `--field-min-font: 16px` now applies to `input`/`select`/`textarea` on coarse pointers and narrow viewports. The alternative fix, `maximum-scale=1` on the viewport meta, disables pinch-zoom for everyone and was rejected.
- **The bottom sheet's grab handle was invisible.** It computed to `height: 0px`: the sheet is a column flex container with a `max-height` while collapsed, so its items shrink to fit, and a 4px handle with the default `flex-shrink: 1` shrank straight to nothing. `flex: none` restores it. That is why the peek read as a cut-off panel rather than something you could pull.
- **Corner buttons no longer stack on each other.** The feed lifts Save to 84px and Grain to 140px to clear the saved-palettes stack, but never lifted Play, so Play (128px) sat *below* Grain and the two overlapped by 32px. Play now takes the same offset at 196px, restoring the even 56px rhythm and clearing the scroll ticker.
- **The Edit FAB no longer covers the keyboard shortcut strip.** Both had claimed the bottom-left corner. The button is now hidden on keyboard devices, where it is redundant twice over — the strip itself reads "E Edit", and clicking the gradient opens the editor. Its media condition is the exact complement of the strip's own, so exactly one is ever on screen.
- **The tab bar fades instead of popping when entering edit.** It used `display: none`, which removes the element from the box tree, so the View Transition could not capture or animate it and the bar vanished in a single frame. It now fades with `opacity` + `pointer-events: none`.

### Removed
- **Boards (collections) deleted.** The feature was unused and its row was the single most expensive block in the mobile gallery header at 86px. Gone: `CollectionsRow`, the `collections`/`activeCollectionId` store slice and its CRUD, the `Collection`/`CollectionLevers` types, the board-detail view, and the destination-aware save on `GradientPage`. Persist migration **v7** deletes the two keys from localStorage; saved gradients are untouched, since a collection only ever held ids pointing into `saved` (covered by a test). `BoardShare` is NOT part of this — despite the name it is the general share/export menu, still used in the feed, gallery and editor.

### Added
- **Pin a stop's position, not just its colour.** Each row in the Colors list now shows its percentage as an editable field with a pin of its own, beside the existing colour lock — a stop is two independent facts (what it is, where it sits) and one combined lock could express neither. A pinned position survives Reset spacing, survives the automatic re-spread on add/delete, and is honoured by generation, so you can nail one stop to 25% and keep rolling for everything else around it. Removing a stop shifts the pins above it down, and dragging a pinned handle carries its pin along rather than snapping back on the next roll. The feed's lock chip counts pinned positions alongside the pinned swatches, because a stop that refuses to move with nothing on screen to explain it looks exactly like a bug.
- **A gradient loading bar for the Community tab.** A cold Supabase fetch showed one line of grey text, which reads as an empty state rather than as work in progress. A colour gradient now sweeps a hairline track while it loads. The motion is deliberately uneven — it covers 170% of the track in the first third of the cycle, 35% in the next, 135% in the last — so it reads as work happening in bursts, the honest shape of a network fetch, instead of implying a completion time it has no way of knowing. Indeterminate by design; `prefers-reduced-motion` holds the band still.

### Changed
- **Gallery ↔ full screen is a zoom, not a cut.** Opening a tile grows it into the full-screen view and closing shrinks it back into the tile it came from, Photos-app style. The tile hands the shared `palette-card` view-transition name to the viewer for the duration and takes it back on close — a name held by two elements at once makes the browser skip the transition outright, which is why the tile drops to `none` while the viewer is mounted. The hand-off needs the tile to be *already* wearing the name when the old state is captured, so the hero id is committed with `flushSync` before the transition starts; setting both in one update captured an old state where nothing owned the name and the viewer faded in from nothing. Scrolling to a neighbour inside the viewer moves the landing tile with it. Every other tile is nameless for the duration: giving each one its own name put it in its own `::view-transition-group`, and groups paint in tree order, so every tile *after* the hero painted on top of the card as it grew — the zoom came apart for every tile except the last one in the grid. Unnamed, they stay inside the root snapshot, which paints below the card.
- **The editor's share button no longer sits on top of the panel.** It was anchored to the right of the *viewport*, which on the desktop layout is the control panel — so it landed on the Shape tiles instead of the gradient. It now steps in by the panel width. That width was two hardcoded copies of `340px`, which is how they got out of step; it is a single `--edit-panel-w` now, read by the panel, the share trigger and the tab bar's centring.
- **Rotated linear/mirror handles drag along the gradient, not straight down.** `projectToTrack` snapped every linear drag to the vertical centre line, but `stopAnchor` places a rotated stop along `(-sin, cos)` through the canvas centre — so on a 45° gradient the handle slid vertically while its siblings sat on a diagonal, leaving the track it was supposed to be riding. The projection is now done on that axis, and in normalized space rather than pixels, because anchors are placed as `(a.x·width, a.y·height)` and a pixel-space projection follows a different diagonal on any non-square canvas. Measured: a dragged handle now lands 0px off the axis where it used to land 171px off it, on the centre line.
- **Horizontal scroll steps the shape in edit mode.** The create feed has had wheel and swipe shape-stepping since it shipped; the editor only had ←/→, so a trackpad swipe that worked full-screen did nothing in the panel. Same state machine as the feed: wheel deltas accumulate per segment and reset on a pause or direction flip, and a touch gesture locks to one axis so a sideways swipe never also scrubs the rolodex.
- **The desktop panel slides in instead of appearing.** The enter motion lived only in `::view-transition-new(edit-sheet)`, so it ran exactly where the View Transitions API is implemented and nowhere else — `withViewTransition` falls straight through to a plain state update otherwise, and the panel simply appeared. (The exit still read as motion, because the sheet is a live element on the way out; that asymmetry is what made it look like a flash.) It is now an ordinary mount animation as well, on the same 320ms decelerate curve, so it is not doubled where the view transition does run: the real element's painting is suppressed while it is captured. Measured entering: x 1280 → 946 → 940.
- **Bottom tabs keep one size in both states.** The active tab was semibold with 22px padding and the inactive one medium with 20px, so "Gallery" grew on both counts every time it became current and shoved its neighbour sideways. One box for both now; the label reserves its bold width with a zero-height `::after` carrying the same string at the heavier weight, so selecting a tab is purely a change of ink. Measured across a switch: 90px and 87px before and after, only `font-weight` differing.
- **The tab bar stops blinking when you switch tabs.** With no view-transition name it was captured inside the root snapshot, and the root cross-fades on every surface switch — so tapping Create faded out the whole tray and faded it back, i.e. the control you just pressed vanished under your finger. It now has its own group, like the title and the Save pill.
- **Stop spacing is yours the moment you touch it.** Adding or deleting a colour used to re-spread every stop evenly, so one delete undid a distribution you had just dragged into place. Re-spreading is now the *default state's* behaviour only: once a stop has been moved, a colour pinned, or a palette opened that already has custom spacing, add and delete leave the positions alone. A **Reset spacing** chip appears in the sheet whenever the stops are off the even ladder and is the deliberate way back — it is the only thing that re-spreads, and it retires as soon as it has. Reordering (the Order chip, a canvas handle swap) is treated as its own case: the ladder of positions is preserved and colours are re-paired onto it, so a sort no longer doubles as a re-spread. `isEvenlyDistributed` compares the **sorted** positions, so a reorder is never mistaken for customizing.
- **The app uses LDS instead of resembling it.** Root typography was `18px/145%` with `0.18px` tracking — a leftover from the portfolio template this app started from, and a step *above* anything on the LDS scale, so every piece of text that didn't set its own size rendered larger and looser than the system says. It now inherits `--text-body` / `--leading-body` / `--tracking-body` (13px, the size `theme-palette` was measured from). Floating chrome is now literally an LDS media button — `lds-btn emph-media emph-media--on-dark` — instead of a hand-mixed lookalike: the `color-mix(currentColor 14%, rgba(20,20,24,.45))` fill, the 26% border, the literal 44px and 13px all have names in the system now (`--media-scrim`, `--target-min`, `--glass-blur`). Class lists live in `lib/mediaChrome.ts` so eight call sites across five files cannot drift apart again. The Effect chips are `lds-chip` / `lds-chip--selected`, and hard-coded sizes, durations and easings across the sheet were replaced with `--size-*`, `--dur-fast`, `--ease-standard`. One caveat worth knowing: `.emph-media--on-dark`'s `color:#fff` is a single class and loses to `.lds-btn.emph-media`'s `color: var(--text)`, which resolved to `currentColor` and inherited `--text-subdued` — so the ink is pinned by `.lds-btn.ghost-chip`, matching specificity. Everything else still derives from that one declaration.
- **The Order chip stops shoving the Effect grid around.** `grid-template-columns: repeat(3, 1fr)` is `minmax(auto, 1fr)`, so the widest nowrap label raised its column's floor and the other two shrank to pay for it — and the Order chip changes width every time you tap it. Cycling the sort visibly resized the whole grid and moved the control out from under your finger between taps. Columns are now `minmax(0, 1fr)`, "Lightness" shortened to "Light" (the accessible name still reads the full key), and the side panel drops to two columns: a third of its fixed 340px is ~98px of content box and "Order: Original" needs 108px, so the longest label was ellipsizing.
- **Pressing S saves the same way clicking Save does.** The keyboard path called the store directly and skipped the flight entirely, so the two ways of doing one thing gave completely different feedback — a gradient sailing into the Gallery for the mouse, a label quietly changing for the keyboard. Both the feed and the editor now launch from the on-screen Save pill via `saveFlightOrigin()`, and both fire only on the way in.
- **Bottom tabs are sized like primary navigation.** They were 36px inside a 4px tray, a step *below* the 44px Save pill opposite them — the least prominent control on screen was the one switching between the app's two halves. Tabs are now `--target-min` at 14px in a 6px tray sitting 22px off the bottom, and the Gallery thumbnail stack grew to 22px to match. The Save pill deliberately did **not** grow with them: it stays one ordinary 44px button.
- **Rotate advertises its keyboard shortcut.** `R` already rotated from anywhere in the editor, but only the shortcut strip said so. The chip now carries an `R` badge, in the same recipe the strip uses, hidden on touch by the same media query — a key badge on a device with no keyboard is noise.
- **Colour-stop handles are inset from the track's edges.** The 28px dots are centred on their position, so at 0% and 100% half the dot hung outside the track — and with the track 16px from the sheet edge, that put the end stops ~2px from the edge of a phone screen, inside the browser's back-swipe gutter: grabbing the first stop navigated the page back instead of dragging. Positions now map through a 20px inset on both sides, gradient fill included so a handle still sits on the colour it marks (measured: leftmost dot edge moved from ~2px to 22px at 390px wide).
- **Dragging a canvas handle no longer moves the desktop panel.** Ducking the chrome slid 340px of side panel off-screen and the flexed preview grew into the space, re-measuring the canvas and re-anchoring every handle — so grabbing a dot made the whole set jump out from under the pointer, and releasing put them back. Two moving parts for a gesture that should have one. The ducking is now mobile-only, where the bottom sheet has the opposite problem and a drag near the bottom edge really does land on the FABs.
- **Floating buttons stop restyling themselves per gradient.** Back, close, share, save, edit and play sampled a palette-derived ink per corner and mixed their fill and border out of it, so every control was a different colour, contrast and apparent weight from its neighbour — and all of them shifted as you scrubbed the feed. `.ghost-chip` is now the bottom tab bar's active-tab recipe, the one thing in the app that already read as stable over anything: a translucent dark base that can't invert on a light gradient, ink pinned at a fixed value, one blur, a hairline border and a small shadow. Call sites no longer pass a `color`. The palette *title* still samples — it is bare text with nothing behind it and has to adapt or disappear.
- **Grain moved off the canvas and into the sheet.** It was a permanent round toggle competing with save and share for the same corner, for a setting people touch once. It is an effect, so it sits with Repeat / Smooth / Hard / Rotate in the Effect section. The bottom-right stack closed up to save (16) / play (72).
- **Palette names draw on a much wider vocabulary.** Names repeated because the pools were small: six color nouns per hue band and one place list meant a gallery of twenty saves surfaced "Terracotta" or "Slate" three or four times. Color nouns doubled to twelve per band, modifiers to thirty per mood, and a new ~200-word reference pool joins them — myth and folklore from several traditions, verse forms, music, festivals, night-sky names, and the untranslatable mood-words other languages have and English doesn't. Single-token, plain-ASCII (these get slugified into share URLs) and public-domain only. Eight name templates instead of three, all still obeying English adjective order — a reference is a head noun, so "Faded Indigo Nocturne" and never the reverse. Saving also names against the board: a collision re-rolls with a salted seed, while an uncollided name stays byte-identical to what that palette has always been called, since share links depend on it.
- **The mobile edit sheet caps at 62dvh and scrolls.** The preview is `flex: 1; min-height: 0` and would happily shrink to nothing to make room for a tall sheet; with the Colors list added it now would. The gradient being edited stays on screen however many stops are listed.
- **The edit sheet is split into Shape and Effect sections.** On mobile a segmented control switches between them; on desktop, where the side panel has the height, both render stacked under headings and there is no switching. This fixes a real dead end: the collapsed peek clipped **214px of controls** behind `overflow: hidden` with no scroll, reachable only by finding a 36×4px grab handle, and nothing on screen said they were there. Both panels stay mounted in either layout — the inactive one is hidden by a class, not unmounted, so desktop can reveal it and no state or focus is lost on switching.
- **The collapsed peek is content-sized instead of a hard-coded height.** Everything below the sections is hidden while collapsed, so the sheet is exactly the handle, the segmented control, and the active section. The two sections differ in height (Shape one 74px row, Effect two rows at 88px), so the rows below start at a different offset per tab and no single pixel value could clear the taller section while stopping short of the colour-stop row for the shorter one. `max-height` remains only as a ceiling so the collapse still animates.
- **Mobile gallery header rebuilt.** It was consuming 324px of an 812px screen — 40% before a single palette appeared — across five stacked blocks, with an action row mixing control heights of 44/29/28/28px on two different baselines. Now three rows totalling **154px (19%)**: tabs; search + layout toggles + share on one line; filter. Every bar control takes a new `--control-h` (36px) with a 44px tap target via the `::after` expansion the chips already used — several controls were previously *below* the 44px minimum while looking larger.
- **All six shapes on one row in the bottom sheet.** The 3-up grid meant two rows of tabs, which is what made the sheet tall and meant the collapsed peek could only ever show half the shapes. Below 768px (wherever the sheet is a bottom sheet rather than the desktop side panel) it is 6-up with smaller squares; the labels still fit — the widest, "Angular", measures 42px at 11px against a ~54px track. The expanded sheet dropped from 68% of the viewport to 40% (tabs 411px to 186px), and the collapsed peek from 166px to 103px, giving the gradient 87%. The preview square is a FIXED 44px rather than a max-width, so the row is exactly as tall at 320px as at 760px — with a cap it grew 6px on a wide sheet and no single peek height could clear the row at one width without slicing it at the other.
- **Filters collapse to a select on mobile.** Fifteen chips wrapped to three rows and cost 90px, and seven of them read "0". Below 640px they become one native `<select>` (OS picker, no overflow, free accessibility); the chip row returns at 640px and up where everything fits at once. Shapes matching nothing are omitted from both — except the currently selected one, which is always kept so it cannot vanish from the control that selects it.
- **The palette title shows it is editable.** It was plain text with no chrome, so the rename was invisible until you happened to click it. Hovering now outlines it as the text field it becomes (`cursor: text`, hairline box in the title's own colour), and the editing state changed from a bottom-border underline to the same full box, so hover to focus is one continuous shape. Hover-capable pointers only, or touch devices latch the outline on after a tap.
- **Export Posts moved into the share menu.** As a labelled 105x29 pill beside the 44x44 icon-only share trigger it was the odd one out in a row where nothing shared a size, and it is a slow bulk action rather than a primary control. It now sits under "More options" with the other bulk exports.
- **Angular honours stop positions** (reversal). Angular spread colours around the circle by index (`i/n`) and discarded positions outright, so dragging a stop emitted byte-identical CSS. Positions now scale by `(n-1)/n`, which reserves the seam its own `360/n` wedge — an evenly spaced ramp lands on exactly the old offsets, so the default is unchanged and only a deliberately uneven ramp differs. Hardened wedges track the same offsets. The original call was made to guarantee N colours read as N equal wedges; that reading survives the scaling, and the inert control did not justify keeping it.
- **Mirror honours stop positions** (reversal). Mirror normalised min–max onto a full 0–100 span before folding, which made it invariant to any shift or stretch of the ramp: `[0,50,100]`, `[10,50,90]` and `[30,65,100]` all produced identical CSS, so dragging either end stop was a no-op. Positions are now halved directly and reflected about the 50% line. A ramp already filling 0–100 is unchanged. The normalisation existed to stop a gap opening at the fold when no stop reached 100; that is now fixed by reflecting the fold stop instead of stretching the ramp to meet it, so a short ramp holds its last colour flat across the middle.
- **Turrell blocks travel nearly the full range.** The extent floor dropped from 0.2 to 0.1, so a stop moves across 90% of the range rather than 80% and the innermost block no longer sits at a fifth of the canvas. It stays well above zero on purpose: layers are blurred 24px by default, so 0.05 (tried, rejected) swallows the innermost colour completely.
- **Drift (the play button) now runs on angular**, which it could not before: every frame used to render identical CSS. Only `square` is still excluded, because Turrell blocks are painted by their own elements and a drifting background-image never reaches them.

### Fixed
- **Four copies of the same geometry, drifting apart.** `gradientColorAt`'s Turrell sampler computed `100 - position * 0.8`, inverting the ramp — it treated position 0 as the outermost layer where the component makes it the innermost, so on-gradient ink was picked against the wrong colour for any square with asymmetric stops. The PNG export compressed angular by `n/(n+1)`, agreeing with neither the CSS nor the sampler, so an exported angular PNG placed every stop differently from the gradient it came from. The export's mirror rebuilt an evenly spaced sequence from hex order, discarding positions. All of these now resolve through the shared `angularSequence` / `mirrorSequence` / `turrellExtent`.

## [Unreleased] - 2026-07-25

### Added
- **Batch Export**: Added an "Export Posts" button to the Gallery header that bundles all saved gradients into a downloadable ZIP file of 1080x1350 PNGs.
- **Instagram Poster Layout**: Added a `post` vignette shape to generate 1080x1350 images for social media sharing. 

### Changed
- **Share Menu Redesign**: Simplified the `BoardShare` dropdown to prioritize a one-tap "Share as Image" and "Copy Link" action, tucking developer/JSON tools behind a "More options •••" overflow menu.
- **Text Alignment**: Changed the poster export text to be left-aligned (6% margin) instead of center-aligned for a more editorial poster quality.
- **Dynamic Text Contrast**: Updated the `titleColorAt` coordinate to sample contrast from the left margin (0.06, 0.5) instead of the dead center (0.5, 0.5) so text remains legible over edge colors (e.g. Hot Terracotta).
- **Turrell Rendering Fix**: Switched Turrell squares from using `ctx.filter = 'blur()'` to `ctx.shadowBlur` during export to prevent rendering bugs on iOS Safari for large canvases.
- **Bug Fix**: Restored missing `index` mapping in `Gallery.tsx` that was causing the cascading animation delay to crash the gallery view.
